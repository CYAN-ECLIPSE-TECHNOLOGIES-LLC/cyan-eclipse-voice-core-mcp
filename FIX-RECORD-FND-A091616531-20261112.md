2. Cure (commit 0334a7e, droplet maintenance home; pushed — GitHub origin/main == 0334a7e)
server.py: t_kill_switch gates before any mutation. The call must carry owner_token, compared in constant time (hmac.compare_digest) against the owner credential in the server process environment, ECLIPSE_VOICE_CORE_OWNER_TOKEN (the server's existing ECLIPSE_VOICE_CORE_* env pattern; the family spec classes the kill switch as an owner act above the tier ladder, and the connector manifest already records it as a human act, not granted — the gate enforces that fence server-side for every stdio caller). Three refusal classes, each emitting a kill_switch_refused receipt (detail: engaged, scope family, reason) before raising, persisted by the server's receipts-grew rule while nothing else changes:
- credential not configured in the server env: KILL_SWITCH_OWNER_TOKEN_NOT_CONFIGURED (fail-closed, both directions);
- owner_token missing or not a non-empty string: KILL_SWITCH_OWNER_TOKEN_REQUIRED;
- owner_token mismatch: KILL_SWITCH_OWNER_TOKEN_INVALID.
On success the prior behavior runs unchanged and the kill_switch_set receipt detail gains actor "owner". The credential is never written to state, fixtures, or receipts. Tool description and inputSchema updated in the TDQS style of the file (owner_token required, purpose stated). tools-manifest.json inputs line for kill_switch_set updated in the repo and in the Muse connector's manifest copy. core_engine.py untouched; freeze semantics untouched.
